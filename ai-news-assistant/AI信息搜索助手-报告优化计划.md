# AI 信息搜索助手 — 可视化报告优化计划

> 版本：v1.0
> 定位：基于对当前报告实现（`templates/report.html` + `report_generator.py`）的深入分析，结合 HF Daily Papers、The Rundown AI、TLDR AI、Datawrapper、Flourish 等标杆产品的调研结论，产出一份**从「工具输出」到「可产品化阅读体验」**的分阶段优化计划。
> 原则：先出计划、经确认后实施；每项优化均标注问题根因、方案、落地位置与验收标准。

## 1. 现状评估

### 1.1 当前报告组成

| 模块 | 现状 |
|---|---|
| 顶部 | 报告标题 + 生成时间 + 摘要段落（`analysis.summary`） |
| 重点信息 | 高亮卡片区（`analysis.highlights`，有 title + why） |
| 分类浏览 | Tab 切换（全部 / 各分类），卡片网格 |
| 信息卡片 | 标题（外链）+ 解读（note）+ 来源标签 + URL 文本 |
| 图表 | Chart.js：来源分布柱状图 / 类别占比环形图 / 标签频次横向条形图 |
| 趋势 | 纯文本列表（`analysis.trends`） |
| 交互 | Tab 过滤、搜索框、排序（标题/来源）、亮/暗主题（localStorage） |
| 形态 | 单文件 HTML，CSS/JS 内联，Chart.js 走 CDN |

### 1.2 现有优点（保留并强化）

- 单文件自包含，双击即读、可随意分发 ✅
- 已有 Tab / 搜索 / 排序 / 主题四类交互，浏览器实测全部正常 ✅
- 数据与展示分离（`task_*.json` → 渲染器），可离线重渲染 ✅

### 1.3 问题诊断（按严重度分级）

| 级别 | 问题 | 根因 |
|---|---|---|
| **P0-1 时效性缺失** | 卡片不展示发布时间；报告无「本期覆盖时间段」 | 模板未使用 `published_at` 字段；stats 未聚合时间跨度 |
| **P0-2 无速览层** | 打开即进入全量卡片，缺乏「3 分钟扫读」入口 | 无 TLDR 速览区、无 Top 精选、无关键指标条 |
| **P0-3 叙事性弱** | 图表无标题/注释/结论，读者要自己读数据 | 模板图表区只有 canvas，无叙事文案；与「带注释图表更受欢迎」的行业结论相悖 |
| **P1-1 缺时间趋势图** | SPEC 承诺「时间趋势折线图」，实际未实现 | `build_chart_data` 只输出 3 组静态图，未按 `published_at` 聚合 |
| **P1-2 信号密度低** | 卡片 note 浅、无「为什么重要」一句话点评；部分卡片 URL 是裸文本 | 报告 JSON 由 LLM 生成，字段约束不足（缺 impact/why 每条目级） |
| **P1-3 缺少来源聚合表** | SPEC 承诺「来源链接表」，实际无 | 模板无数据来源统计与链接区块 |
| **P2-1 交互深度不足** | 无按时间排序、无来源多选过滤、无收藏/已读、无卡片展开详情 | 排序只有标题/来源两项 |
| **P2-2 状态不可分享** | Tab/搜索/排序状态刷新即丢失，无法通过 URL 分享 | 未做 URL 参数同步 |
| **P2-3 移动端未适配** | 卡片栅格与工具栏未做响应式 | CSS 无媒体查询 |
| **P3-1 无障碍欠缺** | 无 aria 标注、对比度未按 WCAG 校验、键盘可达性未验证 | 模板无相关实现 |
| **P3-2 离线降级缺失** | Chart.js CDN 失败时图表区空白且无替代 | 无 onerror 降级 / 数据表格替代 |
| **P3-3 无跨期视角** | 每期孤立，无法与上期对比（新增/消失主题） | 历史报告已在 `data/reports/` + RAG，但未用于报告内对比 |

## 2. 标杆产品调研与可借鉴点

### 2.1 Hugging Face Daily Papers（模型/论文社区日报的标杆）

- **每日精选 + 趋势榜**：社区精选论文 + 点赞投票形成 Trending Papers，热度可排序
- **一页集成**：论文页面右侧聚合关联模型、数据集、Spaces 资源，点击即达
- **互动闭环**：评论 / 讨论 / 认领作者 / 订阅邮件提醒（1.2 万+ 订阅）
- **个性化**：按兴趣推荐相关论文（librarian-bot）
- **可借鉴**：① 报告顶部加「本期热门 Top」榜（按多源提及/去重聚合加权）；② 卡片关联「相关来源」的聚合入口；③ 报告支持「订阅/归档」概念（周报档案索引）

### 2.2 The Rundown AI / TLDR AI（AI 新闻简报的产品范式）

- **5 分钟可扫读结构**：1 条 macro story（主编叙事）+ 5~8 条 short hits（一句点评，非 press release 复读）
- **模块化分区**：核心资讯 / 工具 / 教程分栏，读者按需跳读
- **One-line evaluation**：每个模型/工具附一句「价值判断」，而非搬运原文
- **信号密度**：The Rundown 2M+ 订阅、约 50% 打开率的直接原因
- **可借鉴**：① 报告增加「本期速览（TLDR）」——5 条一句话要点，每条可点击展开详情；② 每条卡片要求「为什么值得关注」一句；③ 顶部指标条（条目数/站点数/时效跨度/热词 Top3），10 秒建立全局感

### 2.3 Datawrapper / Flourish / FT 数据新闻实践

- **带注释的图表比极简图表更受欢迎**（FT 首席数据记者 John Burn-Murdoch 实证研究：叙事性标题 + 箭头注释 + 结论句的图表排名最高）
- **图表即故事**：每张图都要回答一个问题，标题直接给出答案
- **无障碍优先**：Datawrapper 遵循 WCAG 2.1、适配移动端、色盲友好色板（Viridis/Cividis），是 NYT/Guardian 首选
- **交互深化**：Flourish 的 Popups（点击查看详情）+ Filters（下拉筛选）+ 时间轴动画
- **可借鉴**：① 每个图表配叙事性标题 + 数据注解 + 一句话结论；② 配色替换为无障碍色板；③ 响应式布局；④ 图表点击弹详情

### 2.4 提炼：五条核心借鉴原则

1. **可扫读优先**：任何读者 3 分钟内应能带走结论（速览层 + 指标条 + Top 榜）
2. **信号密度**：少而准的点评 > 多而浅的罗列（one-line evaluation）
3. **叙事闭环**：图表必须「标题给答案 + 注释讲过程 + 结论收尾」
4. **时效可视化**：AI 信息的价值核心是「新」，时间必须全程可见
5. **可分享可归档**：状态可分享（URL）、可导出（PDF/PNG）、可对比上期

## 3. 优化目标与设计原则

- **目标**：把报告从「AI 输出的静态文档」升级为「可扫读、可探索、可分享、可归档的交互式信息产品」
- **原则 1**：不新增外部依赖，保持单文件自包含（Chart.js CDN 可降级）
- **原则 2**：数据层先行——先补齐报告 JSON 的字段与聚合，再改模板（`task_*.json` 是唯一数据契约）
- **原则 3**：分层实施，每层独立验收，不阻塞后续层
- **原则 4**：避免过度设计——所有优化项都必须有「当前可用的数据」支撑，不建幻想的字段

### 4.1 三级置信度体系设计（P0.6 详案）

> 目标：让读者打开报告即能回答「这条信息能信几分」。核心原则：**LLM 自评置信度只作参考，规则置信度（来源+时效+多源交叉）是兜底与校准基线**——LLM 不稳定时前端始终有值可显示。

**① 报告级（整体可信度）—— 头部「质量区」**

| 指标 | 计算 | 展示 |
|---|---|---|
| 质量分 | Evaluator 综合评分 `overall`（0~1） | 徽标：≥0.85 优 / ≥0.7 良 / 其余 中，附数值 |
| 数据新鲜度 | 有 `published_at` 条目的平均时效（天）；无时间戳条目标记「近期」 | 一行说明：「覆盖近 N 天 · 其中 X% 条为 24h 内」 |
| 覆盖度 | 成功站点数 / 计划站点数 | 质量区副标注 |

**② 总结级（摘要与分类置信度）—— 摘要区与分类标题**

| 指标 | 计算 | 展示 |
|---|---|---|
| LLM 自评 | Analyzer prompt 增加输出 `confidence`（0~1，含 `reason` 一句话依据），分类级同理 | 摘要区置信度条（进度条样式）+ 分类标题旁小徽标 |
| 数据支撑度 | 该分类条目数 / 多源覆盖数（规则校准，LLM 未输出时兜底） | 与 LLM 自评取平均或取低值 |

**③ 条目级（单条资讯可信度）—— 卡片角标**

置信度分 = 来源可信度 × 时效 × 多源加权（三者合成 0~1）：

| 因子 | 规则 | 权重 |
|---|---|---|
| 来源可信度 | 官方/论文（HuggingFace、arXiv）=1.0；媒体（量子位、WIRED、GitHub Trending）=0.8；未标注=0.5 | 0.5 |
| 时效新鲜度 | 有 `published_at`：≤1 天=1.0，≤3 天=0.8，更久=0.6；无时间=0.7（「近期」） | 0.3 |
| 多源交叉 | 去重聚合中该条被 ≥2 站点提及=1.0，单源=0.8 | 0.2 |

- 展示：卡片右上角角标（高 ≥0.85 绿 / 中 ≥0.6 黄 / 低 红），hover/点击显示三项因子明细
- 数据前提：多源提及数需 `pipeline.py` 去重时记录（`dedup` 阶段统计 url/title 指纹出现次数，写入 `stats` 或条目 `mentions`）

**联动改动清单**
- `evaluator.py`：无需大改，`overall` 已存在
- `analyzer.py`：prompt + schema 增加 `confidence`/`reason`（解析失败则规则兜底）
- `pipeline.py`：去重阶段统计多源提及数
- `report_generator.py`：新增 `build_confidence()`（三级计算）、`build_freshness()`（新鲜度统计）
- `report.html`：头部质量区、摘要置信度条、卡片角标 + tooltip

### O4 — 分享、无障碍与工程（P3 全部）

- 验收：断网可读、打印成 PDF、`test_report.py` 全绿

## 6. 依赖与数据前提（实施前需确认）

1. **published_at 覆盖不全**：量子位/WIRED 无发布时间，P0.1/P1.1 依赖兜底逻辑（视为「近期」或仅统计有时间戳的条目）——需在 `pipeline.py` 统一补
2. **impact/tldr 字段**：依赖 LLM 结构化输出增强（reporter/analyzer 的 prompt + schema），需验证生成稳定性，缺省时前端容错隐藏
3. **历史报告**：跨期对比（P3.4）依赖 `data/reports/task_*.json` 存档，已有 ✅
